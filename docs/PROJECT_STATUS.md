# 功能范围与验证记录说明

## 三板分工

A 负责传感器采集、控制快照调度、事件存储、双串口命令接收、B/C 合成结果汇总、混音与 I2S 输出。B/C 执行硬件合成；C 还监视最终音频并驱动 OLED 和 LED。

基础音色中，B 负责 Do/Re/Mi，C 负责 Fa/Sol/La/Si。大提琴和竹笛加法音色中，B/C 分担七音的低/高谐波分量：每音合计 32 分量，七音最多 224 个分量状态。该架构包含流水线和时分调度，不表示 224 个算术单元都在同一个时钟并行执行，也不表示 32 独立音符复音。

## 已收录功能

七触摸音键、和弦、五音色、ADSR、音高/音量电位器、两片 FSR 全局升降音高、编码器运动颤音、PAJ 手势、四种 OLED 显示、七音 LED 反馈、电脑上位机、手机 BLE 页面、ESP32-C3 桥接和 Flash 控制事件记录/重演代码。

OLED 模式包括音频波形、延迟 XY 李萨如显示、七音指示和实时 256 点 DFT 频谱。电脑波形与 OLED 使用同一最终音频来源，独立采集，刷新率不代表音频延迟。手机端是 Web Bluetooth 页面；iOS 需要支持 Web Bluetooth 的浏览器环境，不能视为 Safari 通用支持或原生 App 安装包。

## 尚不能据此宣称的结论

- 没有整机实测报告时，不宣称已达到 ≤5ms 或 ≤10ms 延迟。
- 32 谐波音色与 32 独立音符的复音指标不同，应由赛题解释和实测结果判断。
- Flash 擦除、录制结束、掉电保存与回放闭环，应在最终接线下重新验收。
- LED 当前为按音反馈；测距模块已停用，历史初始化代码仍保留。
- 三块 20K 通过分工扩展能力，不等同于一块 60K 器件；通信和资源分布有额外开销。

`pin_confirmation.json` 中的 hardware_ready/physical_three_board_test_passed 是历史生成脚本标志，不是最终作品实测成绩。历史文档和报告保留其版本上下文，入口以根目录 README 和工程 CST 为准。

`validation/` 中的编译报告和日志来自原版本。当前 GitHub 打包只核对源文件、工程引用和适用的软件测试，没有重新烧录硬件，也没有重新生成 FPGA 布局布线结果。`performance_preview.png`/`diagnostics_preview.png` 为界面布局预览。

HDL 回归需要 Icarus Verilog；部分脚本保留了原机器的工具路径，使用时先指定工具路径或按本机调整。`run_poly_tests.py` 另需要 NumPy，界面预览工具可能需要 Pillow；日常上位机只需 Python/Tkinter 和 pyserial。
